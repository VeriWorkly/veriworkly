title: List Documents
description: >
  Lists the authenticated user's documents (resumes, cover letters, portfolios,
  link-in-bio

  pages), optionally filtered by type. Soft-deleted documents are excluded.
  Document bodies

  are left out unless `includeContent=true`.


  **Paging.** Send `limit` (and, after the first page, `cursor`) to read the
  list a page at a

  time. Each page adds `nextCursor`, the value to send as `cursor` for the next
  page (`null`

  on the last page), and `total`, the number of live documents of this type.
  Send the same

  `type`, `updatedSince` and `includeContent` on every page of one walk; a
  cursor that was

  not issued for them is rejected with `400` and `details.code`
  `INVALID_DOCUMENT_CURSOR`.


  - The plain list goes newest first, by `updatedAt` then `id`.

  - A sync walk (`updatedSince` set, or `includeContent=true`) goes oldest
  first, by
    `updatedAt` then `id`. A document edited during the walk comes back again on a later
    page, so none is skipped; keep the copy you saw last.
  - With `updatedSince`, documents deleted since then come back in `deleted`,
  also paged
    (up to `limit` per page, oldest deletion first) beside the documents. Keep following
    `nextCursor` until it is `null`.
  - Every page of one walk repeats the first page's `serverTime`. Use it as the
  next
    `updatedSince` only after the last page.

  **Without `limit` or `cursor`** the response is the older single list: up to
  500

  documents, most recently updated first, with no `nextCursor` or `total`. It is
  kept while

  clients move to paging; a later release makes `limit` default to 20.
