  Upgrades the live subscription to the `bundle` in place. As with the preview,
  the body

  accepts any plan and recurring interval, and any change other than that
  upgrade is refused

  with `409` and a `details.code`. The provider charges the prorated

  difference, and the plan, its features and its credits move once that payment
  succeeds and

  its webhook arrives; until then the answer is `status: "pending"`.


  An idempotency key is required, in the `Idempotency-Key` header or as
  `idempotencyKey` in

  the body (the header wins). Retrying with the same key never asks the provider
  twice: it

  returns the stored answer with `replayed: true`. Session-authenticated only;
  blocked for

  non-admins in production during the current rollout phase.
