## Description

Portfolios are published from a single PORTFOLIO-type [Document](/api-reference/documents/overview)
to their own `<name>.veriworkly.com` subdomain, on any plan. The flow is: save a draft (`PUT /portfolios/draft`), preview it,
then publish it (`POST /portfolios/publish`) once the content passes the full validation schema.
The free templates (`signal`, `atelier`) publish on any account and show a VeriWorkly badge.
Premium templates (`nimbus`, `cipher`) need Creator Pro, the Job Hunter Bundle, or a pass. When
that access lapses, a premium portfolio stays online on the closest free template.

<Callout type="warn" title="Publishing is admin-only in production for now">
  In production, `POST /portfolios/publish` currently answers `403` for every account except the
  configured admin, whatever the plan. Everyone can still save drafts, preview, and manage
  everything except putting a portfolio live. This does not apply in development.
</Callout>

The `/portfolios/public*` routes serve published content, only the part a visitor may see, and need
no user session. View tracking is
buffered in Redis, deduplicated per viewer IP for 30 minutes, and flushed to Postgres by a
scheduled job — so `POST /public/{subdomain}/view` returns `202` and does not reflect a persisted
count.

## Authentication

| Method                                                       | Access Level      | Requirement                                      |
| :----------------------------------------------------------- | :---------------- | :----------------------------------------------- |
| `/public`, `/public/{subdomain}`, `/public/{subdomain}/view` | **No session**    | An API key, or a whitelisted first-party origin. |
| All other routes                                             | **Authenticated** | Session cookie only — no API key support.        |

<Callout type="warn" title="“Public” means no user session, not no credentials">
  The `/portfolios/public*` routes do not require a logged-in user, but they are **not** open to
  anonymous callers. A request that carries neither an API key nor a whitelisted first-party
  `Origin`/`Referer` is rejected with `401`.
</Callout>
