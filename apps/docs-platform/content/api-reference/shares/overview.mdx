## Description

Share links let a document owner hand out a public, read-only URL to a static content snapshot
without exposing the live document. Each document can have at most one active share link at a
time — creating a new one replaces the existing one.

Links can optionally be password-protected (scrypt-hashed, verified with a timing-safe comparison
— the hash itself is never returned by any response). Every link expires after 7, 14, 30 or 90
days, or never if asked for with `noExpiry: true`; a link created without either lasts 7 days.

Creating a link requires the owner to have **claimed a username** first, since it forms the public
URL (`/{username}/{slug}`); without one the request fails with `400`.

## Authentication

| Method             | Access Level      | Requirement                                                   |
| :----------------- | :---------------- | :------------------------------------------------------------ |
| `/shares/public/*` | **No session**    | An API key, or a whitelisted first-party origin.              |
| All other routes   | **Authenticated** | Session cookie, or API key with `resume:read`/`resume:write`. |

<Callout type="warn" title="“Public” means no user session, not no credentials">
  The `/shares/public/*` routes do not require a logged-in user, but they are **not** open to
  anonymous callers — a request carrying neither an API key nor a whitelisted first-party
  `Origin`/`Referer` is rejected with `401`.

The password-verification route is additionally rate limited to **3 attempts per 5 minutes per
IP**, far tighter than the rest of the API, to make protected links impractical to brute-force.

</Callout>
