# Resume Templates

VeriWorkly separates professional data (your Master Profile and documents) from visual presentation
(the template). Switching templates never modifies or loses data, so you can cycle through the whole
library to compare layouts.

---

## Dual-engine rendering

Each template is implemented twice against the same data:

1. **Web engine (`web.tsx`)** — React and Tailwind CSS 4, powering the live paged preview.
2. **PDF engine (`pdf.tsx`)** — `@react-pdf/renderer` primitives, producing the exported PDF with
   embedded fonts and real vector text.

Both read the same `ResumeCustomization` object, which is what keeps the preview and the export
visually aligned. See [Export Pipeline](/docs/architecture/pdf-generation).

```typescript
  id: "precision-ats",
  name: "Precision ATS",
  documentType: "RESUME",
  description: "A dense, recruiter-friendly layout …",
  accentColor: "#10b981",
  previewImage: "/templates/resume/precision-ats.png",
  tags: ["One column", "ATS-friendly", "Compact", "Simple"],
} satisfies TemplateMeta;
```

## Customisation

Every template honours the same customisation object:

- **Colours** — accent, body text, muted text, page background, section background, borders, and
  section headings, each independently set.
- **Typography** — font family (which drives PDF font embedding) plus body and heading line heights.
- **Spacing** — section spacing and page padding.
- **Structure** — per-section visibility and ordering, and for two-column templates, a left/right
  column assignment per section.

See [Resume Schema](/docs/architecture/resume-schema#customization) for the full field list.

## Adding a template

1. Create `apps/studio/templates/resume/{your-template}/` containing `meta.ts`, `skin.ts`,
   `web.tsx`, and `pdf.tsx`. Every template is built with `createResumeWebTemplate` /
   `createResumePdfTemplate` from `apps/studio/templates/resume/shared/`, which handle section
   ordering, item content, spacing, and pagination — a skin only supplies a type scale, a header,
   and a section heading.

   Put **every** number in `skin.ts` (the type scale plus a `geometry` object) and read it from
   both `web.tsx` and `pdf.tsx`. Sizes must never be written twice.

2. Register the metadata and web renderer in `apps/studio/templates/index.ts`.
3. Register the PDF component in `apps/studio/templates/resume/pdf/index.ts`.
4. Add the metadata to `apps/studio/features/documents/core/template-catalog.ts` (the picker) and a
   preview asset at `apps/studio/public/templates/resume/{your-template}.(svg|png)`.
5. Verify against `/pdf-debug/resume/{your-template}`, the internal PDF rendering debugger.

`tests/contracts/template-render.contract.test.tsx` fails if steps 2–4 fall out of sync, so a
half-registered template cannot ship, and `template-geometry.contract.test.tsx` lays the PDF out
and checks its real boxes against the scale.

<Callout type="warn" title="A bare number in a react-pdf style means points">
  `@react-pdf/stylesheet` returns unitless values untouched, and even the string `"3px"` is
  converted with a default DPI of 72 — so both mean 3pt, which is 4 CSS pixels. Every spatial value
  in a `pdf.tsx` must go through `pxToPt`. Three more differences the shared engine already
  neutralises: react-pdf inherits a *computed* line height (CSS re-multiplies the unitless factor),
  `align-items: baseline` resolves to bottom alignment, and Yoga shrinks a `flexShrink: 0` box when
  a sibling's minimum content width does not fit.
</Callout>

<Callout type="warn" title="Keep the DOM contract">
  The live preview paginates by walking the direct children of `#resume-container`, expecting each
  `<section>` to be exactly `[heading, itemsContainer]`. A template that wraps sections in extra
  containers — or introduces a full-height sidebar — will not split across pages correctly. The
  shared engine enforces this shape automatically.
</Callout>
