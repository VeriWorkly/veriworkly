**You can get a resume or cover letter out of VeriWorkly in two ways: download it as PDF, DOCX,
HTML, Markdown, plain text or JSON, or publish a read-only share link. Downloads work in guest mode
and are generated in your browser. Share links need an account and a username, and expire after 7
days unless you choose otherwise.**

---

## Which formats can I export a resume in?

Six, from the export menu in the editor:

| Format         | Engine                | Best for                                                           |
| :------------- | :-------------------- | :----------------------------------------------------------------- |
| **PDF**        | `@react-pdf/renderer` | Recruiters and job-board uploads. Vector text with embedded fonts. |
| **DOCX**       | the `docx` package    | Employers that require Word, or further manual editing.            |
| **HTML**       | serialiser            | Embedding or self-hosting.                                         |
| **Markdown**   | serialiser            | Version control and text-based systems.                            |
| **Plain text** | serialiser            | ATS forms that ask you to paste your resume as text.               |
| **JSON**       | serialiser            | Backup, and re-import into VeriWorkly.                             |

<Callout type="info" title="Nothing is uploaded to export">
  All six formats are generated inside your browser. Your document content is never sent to a server
  to be rendered, and there is no headless browser in the pipeline. See [Export
  Pipeline](/docs/architecture/pdf-generation).
</Callout>

### Which format should I send to an ATS?

Use the PDF unless the posting asks for something else. PDF exports render every glyph as real text rather than an image, so applicant tracking systems can
index the full contents, and fonts are embedded so layout does not shift on the reader's machine.

If a system explicitly asks for pasted text, use the **plain text** export rather than copying out of
the PDF. It produces cleaner, more predictable output. For why some PDFs reach a parser empty, read
[why some resume PDFs parse as blank](https://blog.veriworkly.com/why-some-resume-pdfs-parse-as-blank).

### What happens to blank fields?

<Callout type="info" title="Blank fields are omitted">
  Empty dates, company names, and locations are dropped from the export rather than printed as
  placeholders. An entry with a blank **title** gets no placeholder either: it prints without one.
  Give every entry a title, or hide the section.
</Callout>

## How do I share a resume with a link?

Sign in, set a username, and create a share link for the document. It publishes a read-only web
page for the document at `/share/{username}/{slug}`.

### Requirements

- You must be **signed in**.
- You must have set a **username**: share URLs are username-scoped, so sharing is unavailable until
  one exists.

### Link options

<Cards>
  <Card title="Public link" icon={<LinkIcon />}>
    A read-only page anyone with the URL can open. By default, viewers can download it as PDF, HTML or
    DOCX from the share page. Turn off **Allow downloads** to hide those buttons; viewers can still
    save or print the page.
  </Card>

<Card title="Password protection" icon={<ShieldCheck />}>
  Set a password to require it before the document is shown. It can be added or removed at any time
  after the link exists.
</Card>

<Card title="Expiry" icon={<FileText />}>
  A new link expires after 7 days unless you pick 14, 30 or 90 days, or Never. An expired link
  returns `410 Gone`.
</Card>

  <Card title="View analytics" icon={<FileDown />}>
    Each link tracks a total view count and a last-viewed timestamp.
  </Card>
</Cards>

### Important behaviours

<Callout type="warn" title="A share link serves a snapshot, not the live document">
  When you create a share link, VeriWorkly stores a **static copy** of the document as it was at
  that moment. Editing the document afterwards does **not** change what recipients see. You must
  refresh the share link to publish your latest version. This is deliberate: a link you sent to a
  recruiter cannot silently change under them mid-review.
</Callout>

<Callout type="info" title="One share link per document">
  A document has at most one share link (enforced by a database uniqueness constraint on user +
  document). Sharing again updates the existing link rather than creating a second one. Revoking a
  link takes the public page down immediately.
</Callout>

### Security

- Share passwords are hashed with **scrypt** and verified with a timing-safe comparison. They are
  separate from your account credentials. VeriWorkly has no account password at all.
- Password verification is rate-limited to **5 attempts per 5 minutes** per link and client
  network, and a correct password resets the count.
- Every view of the share page adds one to its view count, including a refresh.

## Frequently asked questions

<Accordions>
  <Accordion id="link-expiry" title="How long does a resume share link last?">
    Seven days by default. When you create the link you can pick 7, 14, 30 or 90 days, or Never.
    After it expires the page returns `410 Gone`, and you can share the document again to publish a
    fresh link. Revoking a link takes the page down at once, whatever its expiry.
  </Accordion>
  <Accordion id="link-update" title="Does a share link update when I edit my resume?">
    No. A share link serves a copy of the document taken when you shared it, so a recruiter never
    sees it change mid-review. To publish your latest edits, share the document again: it updates
    the same link rather than creating a second one.
  </Accordion>
  <Accordion id="docx-or-pdf" title="Should I send my resume as a PDF or a Word file?">
    Send a PDF unless the employer asks for Word. A VeriWorkly PDF keeps its layout on any machine
    and holds real, readable text. Some recruiters and older systems ask for DOCX so they can edit
    or re-format it; export DOCX for those.
  </Accordion>
</Accordions>
