---
title: Environment Variables
description: Complete configuration reference for the VeriWorkly backend and frontend applications.
---

Every configuration key across the VeriWorkly ecosystem. Defaults are the values the code falls back
to when the variable is unset. They are not necessarily safe for production.

<Callout type="warn" title="Production boots are validated">
  When `NODE_ENV=production`, the API runs a configuration validator in the master process **before
  any worker starts**, and refuses to boot if a required value is missing or unsafe. See [Production
  requirements](#production-requirements) below.
</Callout>

---

## Frontend applications

Each app reads its own `apps/{app}/.env`. A variable only does something in the apps listed under
"Read by". `NEXT_PUBLIC_*` values are inlined into the browser bundle at build time, so changing one
needs a rebuild.

| Variable                      | Read by                 | Description                                                                                                                                                                | Example                        |
| :---------------------------- | :---------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------- |
| `NEXT_PUBLIC_BACKEND_URL`     | studio, site, portfolio | The API address the browser calls. Build time.                                                                                                                             | `http://localhost:8080/api/v1` |
| `BACKEND_INTERNAL_URL`        | studio, site, portfolio | The API address server-side rendering calls. In Docker, the service name.                                                                                                  | `http://api:8080/api/v1`       |
| `NEXT_PUBLIC_SITE_URL`        | site                    | The marketing site's own origin, no trailing slash. Falls back to `https://veriworkly.com`.                                                                                | `http://localhost:3000`        |
| `NEXT_PUBLIC_APP_URL`         | studio, portfolio       | Studio: its own public origin (canonical URLs, sitemap, robots). Portfolio: the base URL its OG image route uses.                                                          | `http://localhost:3001`        |
| `SITE_URL`                    | blog, docs, portfolio   | The app's own public URL. The portfolio also sends it as `Origin` on server-side API calls. The studio does not read it.                                                   | `http://localhost:3004`        |
| `ADMIN_EMAIL`                 | studio, portfolio       | Server-only, never sent to the browser. Identifies the admin account. Use the same value as the API.                                                                       | `admin@example.com`            |
| `INTERNAL_API_KEY`            | studio, site            | Server-only. Same value as the API's `INTERNAL_API_KEY`. Lets server renders pass the visitor's IP, so the API rate-limits each visitor instead of the app as one client.  | —                              |
| `AFFILIATE_PROGRAM_ENABLED`   | studio, site            | Shows the affiliate pages. Read at runtime. Empty means on in development and off in production. Accepts `1`, `true`, `yes`, `on`.                                         | —                              |
| `AMBASSADOR_PROGRAM_ENABLED`  | studio, site            | The same, for the ambassador pages.                                                                                                                                        | —                              |
| `SITE_REVALIDATE_SECRET`      | site                    | Turns on `POST /api/revalidate`, which the API calls after a changelog sync or a roadmap edit. Same value as the API's, at least 32 characters. Empty turns the route off. | —                              |
| `ERROR_REPORT_URL`            | site                    | Optional receiver for server error reports, as plain JSON. Empty writes errors to stderr.                                                                                  | —                              |
| `NEXT_PUBLIC_VITALS_URL`      | site                    | Optional receiver for Web Vitals, as plain JSON. Empty sends nothing.                                                                                                      | —                              |
| `BUILD_STANDALONE`            | site                    | Set to `1` only for container builds that run `node apps/site/server.js` (Next.js `standalone` output).                                                                    | —                              |
| `ALLOWED_ORIGINS`             | docs                    | Origins the docs platform's API proxy route accepts.                                                                                                                       | `https://api.veriworkly.com`   |
| `PORTFOLIO_REVALIDATE_SECRET` | portfolio               | Shared secret for the API's cache-revalidation call after a publish. Must match the API's value.                                                                           | —                              |

<Callout type="info" title="The growth-program flags are read per app">
  The API, the studio and the site each read their own copy of `AFFILIATE_PROGRAM_ENABLED` and
  `AMBASSADOR_PROGRAM_ENABLED`. Set the same value in all three, or a page can show a program the
  API refuses.
</Callout>

`AUTH_SECRET` is read by the API only. No frontend app needs it.

## Backend (`apps/server/.env`)

The template is `apps/server/.env.example`. Every variable below is read by the server.

### Core runtime

| Variable                             | Description                                                                                                                                                          | Default                                        |
| :----------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------- |
| `NODE_ENV`                           | `development`, `production`, or `test`. Any other value stops the boot.                                                                                              | `development`                                  |
| `PORT`                               | Port the API listens on.                                                                                                                                             | `8080`                                         |
| `TRUST_PROXY`                        | Express trust-proxy setting: the number of proxy hops in front of the API, or a comma-separated list of IPs, CIDRs, `loopback`, `linklocal` or `uniquelocal`.        | `false`                                        |
| `DIRECT_EXPOSURE`                    | Set to `1`, together with `TRUST_PROXY=0`, only for a production API with no proxy in front.                                                                         | unset                                          |
| `ALLOWED_ORIGINS`                    | Comma-separated CORS allowlist, also used as Better Auth's trusted origins. Each entry must be a bare origin (no path, no trailing slash).                           | Ports 3000–3004 and 8080 on `http://localhost` |
| `ALLOWED_HOSTS`                      | Extra `Host` names the auth routes answer to. The host of `AUTH_BASE_URL` and loopback are always accepted; any other host gets `400`.                               | unset                                          |
| `LOG_LEVEL`                          | `debug`, `info`, `warn`, or `error`.                                                                                                                                 | `info`                                         |
| `ANALYTICS_HASH_PEPPER`              | Pepper for the one-way visitor hashes used in analytics. Production refuses the example value.                                                                       | `veriworkly-analytics-pepper`                  |
| `CLUSTERING_ENABLED`                 | Run several worker processes via `throng`.                                                                                                                           | `true` in production, `false` otherwise        |
| `WEB_CONCURRENCY` / `SERVER_WORKERS` | Worker count. Required in production; elsewhere it falls back to the CPU count.                                                                                      | CPU count                                      |
| `CRON_ROLE`                          | `all`: every worker schedules the background jobs, and a Redis lock picks one runner per tick. `none`: an API-only replica that schedules no jobs.                   | `all`                                          |
| `MAX_MEMORY_ENTRIES`                 | Cap on the in-memory rate-limit map used when Redis does not answer. Oldest entries are evicted first.                                                               | `15000`                                        |
| `STATS_INTERNAL_KEY`                 | `x-internal-key` value that marks a `POST /api/v1/stats/events` call as internal. Unset: no internal callers. At least 32 characters in production.                  | unset                                          |
| `INTERNAL_API_KEY`                   | `x-internal-key` value that lets the studio and site name the visitor's IP. Also unlocks `/health/metrics` and `/health/jobs`. At least 32 characters in production. | unset                                          |

<Callout type="warn" title="`TRUST_PROXY` must be a hop count or an address list in production">
  `true` trusts every hop, which lets a client spoof `X-Forwarded-For` and defeat IP-based rate
  limiting. `false` or unset puts every client behind the proxy's one IP. Production refuses both:
  set a hop count (for example `1` behind a single nginx) or an IP/CIDR list.
</Callout>

### Database and cache

| Variable                            | Required          | Description                                                                                                                                                                                                     | Default                            |
| :---------------------------------- | :---------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------- |
| `DATABASE_URL`                      | Yes               | PostgreSQL connection string for the app's pool. On Neon this is normally the `-pooler` host.                                                                                                                   | —                                  |
| `DIRECT_DATABASE_URL`               | No                | Direct (non-pooled) connection for `prisma migrate deploy`. Migrations take an advisory lock that does not survive a transaction pooler.                                                                        | —                                  |
| `SHADOW_DATABASE_URL`               | No                | Empty database used only by `migrate dev` and the drift check. Never a production database.                                                                                                                     | —                                  |
| `DB_POOL_MAX_TOTAL`                 | No                | Connection budget for one replica (the process and all its workers). Each worker opens `max(2, DB_POOL_MAX_TOTAL / workers)`. Keep it under about 80% of Postgres' `max_connections`.                           | `80` in production, `10` otherwise |
| `DB_POOL_MAX`                       | No                | Explicit per-process override. Leave unset unless PgBouncer sits in front in transaction mode.                                                                                                                  | derived from `DB_POOL_MAX_TOTAL`   |
| `DB_POOL_IDLE_TIMEOUT_MS`           | No                | Idle time before a pooled connection is closed.                                                                                                                                                                 | `15000`                            |
| `DB_POOL_CONNECTION_TIMEOUT_MS`     | No                | Longest wait to get a connection from the pool.                                                                                                                                                                 | `30000`                            |
| `DB_POOL_STATEMENT_TIMEOUT_MS`      | No                | Postgres statement timeout.                                                                                                                                                                                     | `30000`                            |
| `DB_IDLE_IN_TRANSACTION_TIMEOUT_MS` | No                | Opt-in. Ends a session left idle inside an open transaction. It is sent as a connection startup parameter, which Neon's pooler refuses: behind a pooler, set `idle_in_transaction_session_timeout` on the role. | unset                              |
| `REDIS_URL`                         | Yes in production | Redis connection string (`redis://` or `rediss://`). Sessions, rate limiting, quotas, view buffers and job locks use it. With Docker Compose, leave it unset and set `REDIS_PASSWORD`.                          | `redis://localhost:6379`           |
| `REDIS_PASSWORD`                    | Compose only      | Starts the bundled Redis with `--requirepass`. `REDIS_URL` then defaults to `redis://:<password>@redis:6379`. Use letters and digits only.                                                                      | —                                  |
| `REDIS_MAXMEMORY`                   | Compose only      | Memory ceiling for the bundled Redis (`--maxmemory`, policy `volatile-lru`).                                                                                                                                    | `256mb`                            |
| `REDIS_BOOT_TIMEOUT_MS`             | No                | How long a worker waits for Redis at boot. A wrong password exits at once.                                                                                                                                      | `15000`                            |
| `REDIS_COMMAND_TIMEOUT_MS`          | No                | Longest wait for any Redis reply before the caller falls back.                                                                                                                                                  | `500`                              |

<Callout type="warn" title="The pool budget covers every worker">
  With clustering on, each worker opens its own pool, so what must fit inside Postgres'
  `max_connections` is (pool size × workers × replicas). The API logs a warning at boot if
  `DB_POOL_MAX × workers` exceeds `DB_POOL_MAX_TOTAL`.
</Callout>

| `AUTH_OTP_TTL_SECONDS`               | Email OTP validity window.                                                                      | `300` (5 minutes)                                                             |

| `ADMIN_EMAIL`                        | The admin account, created on first boot. One plain address. **Required in every environment.** | —                                                                             |

### Rate limiting

| Variable                         | Description                                                                                                                     | Default               |
| :------------------------------- | :------------------------------------------------------------------------------------------------------------------------------ | :-------------------- |
| `RATE_LIMIT_WINDOW_MS`           | Per-route window.                                                                                                               | `900000` (15 minutes) |
| `RATE_LIMIT_MAX_REQUESTS`        | Per-route limit per window.                                                                                                     | `100`                 |
| `AUTH_RATE_LIMIT_WINDOW_MS`      | Window for `/api/v1/auth/*`.                                                                                                    | `60000`               |
| `AUTH_RATE_LIMIT_MAX_REQUESTS`   | Limit for `/api/v1/auth/*`.                                                                                                     | `20`                  |
| `GLOBAL_RATE_LIMIT_WINDOW_MS`    | Window for the coarse per-IP ceiling underneath the per-route buckets.                                                          | `900000`              |
| `GLOBAL_RATE_LIMIT_MAX_REQUESTS` | That ceiling. Should sit well above any real single-user session.                                                               | `1000`                |
| `RATE_LIMIT_REDIS_TIMEOUT_MS`    | How long the limiter waits for Redis before counting in process memory. After 3 timeouts in a row it skips Redis for 5 seconds. | `400`                 |

<Callout type="info" title="Why there are two IP buckets">
  The per-route limits are keyed by (method, path, IP), so they bound each endpoint independently
  and never bound a client's total load. `GLOBAL_RATE_LIMIT_*` is the ceiling underneath them.
</Callout>

Some limits are fixed in code and ignore the settings above:

- Share-password verification: 20 per 5 minutes per IP, and 5 attempts per link and IP.
- The public contact form: 5 per hour.
- Client error reports: 10 per minute.
- Usage-metric ingestion: 15 per minute.
- Document and master-profile updates (autosave): 600 per 15 minutes per user.

The Dodo billing webhook is exempt from IP rate limiting: it is authenticated by its signature.
`/health/metrics` and `/health/jobs` are exempt when called with the internal key.

### Request body limits

Body sizes are fixed in code, not set by variables. JSON bodies are capped at 100 KB, except: 4 MB
for documents, the master profile and imports, share creation and the portfolio draft; 256 KB for
the AI routes and the ATS check, analyze and convert routes; 1 MB for the billing webhook.

### Private AI policies

There are **three independent private policies**, each with its own `_PATH` / `_JSON` pair. Point
`_PATH` at a mounted, gitignored file with the name below, or inject the same JSON inline through
`_JSON`; `_JSON` wins when both are set. None of them is safe to commit.

| Variable pair                                       | File                     | Governs                                                                                             |
| :-------------------------------------------------- | :----------------------- | :-------------------------------------------------------------------------------------------------- |
| `AI_ACTIONS_POLICY_PATH` / `AI_ACTIONS_POLICY_JSON` | `ai-actions-policy.json` | General AI writing actions (rewrite, generate, tailor): model routing, prompts, and credit costs.   |
| `ATS_AI_POLICY_PATH` / `ATS_AI_POLICY_JSON`         | `ats-ai-policy.json`     | The ATS AI-analysis layer (`/ats/analyze` insights and `/ats/convert-resume`): prompts and pricing. |
| `ATS_ENGINE_POLICY_PATH` / `ATS_ENGINE_POLICY_JSON` | `ats-engine-policy.json` | The deterministic ATS scoring engine: rule weights, regex patterns, and the keyword dictionary.     |

The engine policy must be built for the version of `@veriworkly/ats-engine` the server runs. Each
engine release can refuse fields or patterns an older one accepted, and the server refuses to start
with a policy its engine rejects.

<Callout type="info" title="Why these are private, and what happens when they are missing">
  Per-action prompts, model selection, token limits, and **credit costs** live in policy files
  rather than application code. The scoring engine's weights and keyword dictionary in particular
  must stay private, or the ATS score becomes gameable. A request needing an unconfigured policy
  fails with `503 <policy name> is not configured.` In production the API also checks at boot that
  the actions policy defines both a `standard` and an `expert` tier for every action, and refuses
  to start otherwise.
</Callout>

### Data retention

A job runs daily at 03:15 UTC and deletes or redacts old rows. Each rule has its own setting, in
days. `0` turns a rule off. If every rule is `0`, the job is not scheduled.

| Variable                                     | What it removes                                                                                                                                                  | Default          |
| :------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| `RETENTION_EXPIRED_SESSION_DAYS`             | Sessions, this many days after they expired.                                                                                                                     | `1`              |
| `RETENTION_EXPIRED_VERIFICATION_DAYS`        | Login codes and email links, this many days after they expired.                                                                                                  | `1`              |

## Production requirements

The API checks its environment at boot and stops with one message that names every failing
variable.

**Always checked (all environments)**

- `NODE_ENV` is `development`, `production` or `test`.
- `ADMIN_EMAIL` is set to one plain email address.
- Every numeric setting is an integer inside its allowed range.
- `AUTH_IP_ADDRESS_HEADERS` does not include `x-forwarded-client-ip`.
- When `AUTH_EMAIL_PROVIDER=smtp`, the SMTP host, user, and password are all set.
- When `AUTH_EMAIL_PROVIDER=resend`, `RESEND_API_KEY` is set.

**Production only**

- `AUTH_EMAIL_PROVIDER` is `resend` or `smtp` (the `console` provider is rejected in production).
- `TRUST_PROXY` is set to a hop count of at least `1` or an IP/CIDR list. `0` is allowed only with
  `DIRECT_EXPOSURE=1`.
- `WEB_CONCURRENCY`, `DATABASE_URL`, `REDIS_URL` and `ALLOWED_ORIGINS` are set.
- `ALLOWED_ORIGINS` entries, `AUTH_BASE_URL`, `PORTFOLIO_URL` and the three Dodo redirect URLs are
  public `https://` URLs, not localhost. `STUDIO_URL`, `STUDIO_LOGIN_URL`, `SITE_URL` and
  `NEXT_PUBLIC_APP_URL` follow the same rule when set.
- `AUTH_SECRET` is at least 32 characters and not an example value.
- `API_KEY_HASH_SECRET` is set, is not the example value, and differs from `AUTH_SECRET`.
- `ANALYTICS_HASH_PEPPER` and `PORTFOLIO_REVALIDATE_SECRET` are set and are not the example values.
- `STATS_INTERNAL_KEY`, `INTERNAL_API_KEY` and `SITE_REVALIDATE_SECRET` are at least 32 characters
  when set. `STATS_INTERNAL_KEY` differs from `INTERNAL_API_KEY`. `SITE_URL` is set when
  `SITE_REVALIDATE_SECRET` is.
- `AI_API_KEY` is set, and the AI policy defines both modes for every action.
- `DODO_PAYMENTS_API_KEY` and `DODO_PAYMENTS_WEBHOOK_SECRET` are set.
- All five `R2_*` variables are set.
