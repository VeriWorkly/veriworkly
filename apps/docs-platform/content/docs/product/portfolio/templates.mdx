Four templates, sourced from a **private git submodule** (`apps/portfolio/template-library`, pinned
to a specific upstream commit) and rendered server-side.

| Template    | Access         |
| :---------- | :------------- |
| **Signal**  | Free (default) |
| **Atelier** | Free           |
| **Nimbus**  | **Premium**    |
| **Cipher**  | **Premium**    |

---

## Free and premium templates

Signal and Atelier are free. Once publishing opens at launch, anyone can publish them on their own
`<name>.veriworkly.com` subdomain, and a published free portfolio carries the "Built with VeriWorkly" badge.

Nimbus and Cipher are premium. Premium gating is enforced at publish time, not just in the picker:

- Any account can **select and preview** Nimbus or Cipher freely.
- **Publishing** (or re-publishing after an edit) with a premium template is refused without the
  `portfolio_publish` entitlement, which comes with Creator Pro, the Job Hunter Bundle, or a pass.
  See [Billing & Credits](/docs/product/billing-and-credits).

When paid access ends, a premium portfolio is not taken offline. After any grace period it moves to
the closest free template (Nimbus to Atelier, Cipher to Signal) and shows the badge.

Publishing opens to everyone at launch. Today it is admin-only in production.

## No custom domains

<Callout type="warn" title="Only VeriWorkly-issued addresses are supported">
  Custom domains are not supported. Every published portfolio, free or paid, is served on its own `
  {your - slug}.veriworkly.com` subdomain.
</Callout>

## How the registry works

`template-library/registry.ts` maps each template id to its metadata and a lazy `loader`:

```typescript
export const templatesRegistry = {
  signal: {
    name: "Signal",
    note: "…",
    mood: "…",
    audience: "…",
    strengths: ["…"],
    image: "/templates/signal-template-preview.png",
    isPremium: false,
    loader: () => import("./signal/SignalTemplate"),
    design: signalDesign,
  },
  // atelier, nimbus, cipher …
} satisfies Record<string, TemplateRegistryEntry>;
```

`apps/portfolio/templates/catalog/templates.ts` derives the public gallery list from that registry,
so the gallery and the renderer can never drift apart. `isPremiumTemplate(id)` is the single source
of truth for gating in the portfolio app.

The backend's publish validator independently accepts only
`"signal" | "atelier" | "nimbus" | "cipher"`, so an unknown template id is rejected server-side even
if a client sends one. Its `PREMIUM_PORTFOLIO_TEMPLATE_IDS` list (`nimbus`, `cipher`) is what the
server gates on.

## Adding a template

Because templates live in a private submodule, this is not an open contribution path today. For
maintainers, the steps are:

1. Add a folder in `template-library/` with its React component, a `design.ts` detail file, and an
   optional scoped stylesheet.
2. Register it in `template-library/registry.ts` with its metadata, `isPremium` flag, and loader.
3. Add the template id to `PORTFOLIO_TEMPLATE_IDS` in
   `apps/server/src/validators/portfolioValidator.ts`, and to `PREMIUM_PORTFOLIO_TEMPLATE_IDS` there
   if it is premium. A premium template also needs a free fallback in `FREE_TEMPLATE_FOR_PREMIUM`
   (`apps/server/src/services/portfolioService.ts`).
4. Advance the submodule pointer in the main repository.
