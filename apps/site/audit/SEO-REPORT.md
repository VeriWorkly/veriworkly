### Host and Search Console actions (the user)

1. **301 `http://veriworkly.com/*` to `https://`** at nginx. Live check 2026-10-24: `http://veriworkly.com/` answers 200, `http://www.veriworkly.com/` 301s. HSTS only helps repeat visitors (W-004). This removes 8 duplicate URLs and stops Google crawling the http copies.
2. **Resubmit the sitemaps** after Phase 1 ships, and open the `veriworkly.com/sitemap.xml` row in Search Console to read the 14 warnings (the API does not return their text). Likely causes: the roadmap item URLs are missing entirely from the live sitemap (0 `/roadmap/<id>` rows on 2026-10-24, W-012), and `/affiliate`, `/ambassador` are listed while the programs are off.
3. **Remove or fix `app.veriworkly.com/sitemap.xml`**: it has 1 error, its only URL is `/login`, and the host is robots-blocked. A login page does not belong in a sitemap.
4. **Validate the fixes** in the Pages report after each deploy: "Not found (404)" (W-003 links), "Soft 404" (template redirects), "Excluded by noindex" (roadmap items), "Alternate page with proper canonical" (roadmap and template query strings).
5. **Bing**: nothing to fix on the site side. Re-check the query report in 4 weeks. Use `GetCrawlIssues` per day if the 4xx count rises.
6. **Wildcard subdomains** `hello.veriworkly.com` (listed in the portfolio sitemap) and any unknown name serve the hosting panel page (FASTPANEL, 200, noindex). Route `*.veriworkly.com` to the portfolio app with a default server that 404s, and drop unreachable portfolios from the portfolio sitemap (SEARCH-DATA SC-03). `janedoe.veriworkly.com` is crawled too.

## 7. Limits of this data

19 clicks in 90 days is a small sample; treat CTR as directional and positions for queries under 20 impressions as noisy. Search Console's query list hides low-volume queries, so the 843 query impressions do not sum to the 2,371 page impressions. The coverage buckets are from the 2026-10-15 export (rows to 2026-10-09); the API does not expose them, so they will only update when the user exports again. The live crawl in this report was one fetch per URL with a generic user agent; it cannot see what Googlebot rendered on the day it crawled.
